# T7 — Participants can aim Roomy by addressing it

**Status:** merged (C4 PASS)
**Model:** gpt-5.6-luna @ max · **Escalate to:** gpt-5.6-sol @ xhigh
**Wave:** 4 · **Branches:** `ticket/T7`

## Context

Roomy turns live speech into a shared canvas of mermaid diagrams. Read `CLAUDE.md` and
`docs/pipeline.md`. After T3 and T5 (on `main`), transcript flows through the journal:
segments close, commit, and produce ops via the prompts in `src/prompt.ts`.

Roomy is silent and takes no instructions. People will want to aim it: "Roomy, draw
that as a sequence diagram", "Roomy, drop the timeline", "Roomy, focus on the auth part".

## Problem

An utterance addressed to Roomy is currently treated as conversation: it gets drawn, or
summarised, instead of obeyed.

## Solution direction

Detection is dumb and deterministic: an utterance whose text, lowercased and trimmed of
punctuation, begins with `roomy` is a **steering utterance**. Nothing else is. No
command grammar, no intent classification.

A steering utterance closes the live segment (it is not part of anyone's thought) and
becomes an **instruction** attached to the next commit: the commit prompt receives it in
a clearly delimited section ("A participant asked: …") and is told to follow it where
the ops contract allows. If the instruction refers to a block ("the timeline"), the
model resolves it against titles and ids on the stable canvas — that is what the model
is for. The instruction is consumed by that commit and not carried further. If no
commit follows within `SEGMENT_PAUSE_MS`, force one so the instruction is not left
waiting for someone to speak.

Steering utterances still appear in the transcript, marked so the client can style
them differently (an `instruction: true` flag on the `utterance` message; clients that
ignore it behave correctly).

Latitude: the prompt wording; whether speculate also sees a pending instruction (it may,
if cheap). Not open: any parsing beyond the leading-word check; a chat UI; any new
message type beyond the flag above.
