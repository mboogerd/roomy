# T4 — The canvas reads like a shared board, not a stacked log

**Status:** not-started
**Model:** gpt-5.6-luna @ max · **Escalate to:** gpt-5.6-sol @ xhigh
**Wave:** 2 · **Branches:** `ticket/T4`

## Context

Roomy turns live speech into a shared canvas of mermaid diagrams that several people
watch at once from their own browsers. Read `CLAUDE.md`. The client is one file,
`public/index.html`, no build step, mermaid from the CDN. After T2 (on `main`) it is
slug-aware, asks for a name once, and receives `presence` messages.

## Problem

- Blocks render as a full-width vertical stack (`public/index.html`, `#canvas` styles
  and `draw()`), so a small mindmap and a wide sequence diagram get the same column and
  most of a large screen is empty.
- The "changed" flash is a border animation that is easy to miss and, on fast updates,
  never stops.
- The transcript pane is a plain list with no visual rhythm; twenty minutes of it is tiring.
- Presence, added by T2, is functional but not designed.
- The mic button has no visible recording state, and a browser without Web Speech gets
  an `alert()`.

## Solution direction

This is a design ticket executed headlessly, so the criteria are structural where they
can be and described where they cannot. The orchestrator will look at the result in a
browser after merge; write your report so that look is quick.

- Layout: diagrams sized to their content, flowing in a wrap-around grid or masonry on
  wide screens and a single column below ~900px. Markdown blocks narrower than diagrams.
  CSS only — grid/flex, `max-width`, no JS measurement unless unavoidable.
- Change signal: a brief highlight that resolves on its own and re-triggers cleanly on
  the next change. If T3 has merged and `state` messages carry `speculative`, style those
  blocks visibly provisional (e.g. reduced opacity or a dashed border) — feature-detect
  the field; do not depend on it.
- Transcript: speaker turns grouped, timestamps or relative time, readable line length,
  auto-scroll that stops when the user scrolls up.
- Presence: visible, quiet, current speaker (last utterance) subtly marked.
- Mic: obvious recording state; a non-blocking inline message instead of `alert()` when
  `SpeechRecognition` is absent.
- Keep dark mode working (`prefers-color-scheme` is already in the stylesheet).

Latitude: everything visual. Not open: no framework, no build step, no dependency, no
second CDN import, no drag-and-drop, no hand-editing of blocks, no changes to any
server message shape.
