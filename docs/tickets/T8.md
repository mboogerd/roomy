# T8 — An external transcript source can post into a room safely

**Status:** merged (C4 PASS)
**Model:** gpt-5.6-luna @ max · **Escalate to:** gpt-5.6-sol @ xhigh
**Wave:** 4 · **Branches:** `ticket/T8`

## Context

Roomy turns live speech into a shared canvas. Read `CLAUDE.md` and the "Where this is
going" section of `BACKLOG.md`. Each participant's browser is a transcript source that
posts to `/r/<slug>/utterance` (from T2). Frozen contract 5 says `Room.say()` is the only
way transcript enters the system — that is about `Room`; HTTP may have more than one
route as long as each one calls `say()`.

A meeting bot — Recall.ai, a Teams app, a Slack huddle listener — would post transcript
into a room exactly the way a browser does, except that it is not our page, it speaks
for many people, and it must not be spoofable by anyone who knows a slug.

## Problem

- `/r/<slug>/utterance` trusts the body's `speaker` and has no authentication, which is
  acceptable for a browser on a PoC and unacceptable for an endpoint a bot would use.
- The request body is read without a size limit (`src/server.ts`, the `json()` helper).
- The payload is undocumented.

## Solution direction

Add `POST /r/<slug>/ingest`. It requires header `x-roomy-secret` equal to
`ROOMY_INGEST_SECRET` from the environment; if the env var is unset, the route is
disabled and returns 404. Compare in constant time (`crypto.timingSafeEqual`). Body is
JSON `{ speaker: string, text: string, t_ms?: number }`, at most 16 KB — apply the limit
in the shared `json()` helper so the browser route gets it too. Reject with 400 on a bad
shape, 401 on a bad secret, 413 on size. On success call `room.say()` exactly as the
browser route does; `t_ms` defaults to now.

Do not change the browser route's behaviour.

Document the payload and the secret in a short section of `CLAUDE.md` ("Posting
transcript from outside"). Prove it with `src/ingest-demo.ts`: a script that reads a
fixture and posts its utterances to a running server with the secret, in order, at a
given speed — `npm run ingest -- <slug> <fixture> <speed>`. It is deliberately not part
of the server process.

Latitude: error message wording; whether `ingest-demo.ts` shares code with `replay.ts`.
Not open: any vendor's API; OAuth; a bot; per-participant keys.

## Acceptance criteria

- [ ] With `ROOMY_INGEST_SECRET` set: correct secret → utterance reaches SSE subscribers with the posted speaker; wrong or missing secret → 401 and nothing is said
- [ ] With it unset: the route is 404
- [ ] A 20 KB body → 413 on both `/ingest` and `/utterance`
- [ ] Malformed body → 400
- [ ] `npm run ingest -- <slug> incident-review 20` against a running server builds a canvas in that room (described in the report)
- [ ] `CLAUDE.md` documents the payload
