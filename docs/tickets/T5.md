# T5 — Each conversation produces a diagram its participants recognise

**Status:** merged (C3 PASS)
**Model:** gpt-5.6-luna @ max · **Escalate to:** gpt-5.6-sol @ xhigh
**Wave:** 3 · **Branches:** `ticket/T5`

## Context

Roomy turns live speech into a shared canvas of mermaid diagrams. Read `CLAUDE.md`, then
`docs/pipeline.md`. After T3 (on `main`) the pipeline is the journal: a fast speculate
prompt on the live segment, a commit prompt on each closed segment, a Sonnet restructure
pass every `RESTRUCTURE_EVERY` commits. All prompt text lives in `src/prompt.ts`. The eval
harness (`npm run eval -- <fixture>`, from T1) writes a skimmable report per fixture.

This is the one ticket in the run whose output is judged by reading, not by a test.
Automated tests must not call the network; eval reports are evidence attached to your
completion report.

## Problem

Observed before T3, with the tick prompt: the model reaches for markdown notes when the
conversation has a shape, and never uses sequence, state or class diagrams. On the
incident fixture it produced a timeline only after a prompt nudge; on the architecture
debate it produced action items and no picture of the disagreement. Speculate and commit
prompts have not been tuned at all — T3 wrote them to work, not to be good.

The restructure pass has never been observed to fire on real input.

## Solution direction

**Part one — diagram choice.** Iterate on `src/prompt.ts` with the eval harness until
each fixture yields at least one diagram a participant would recognise as the shape of
their own conversation:

- `architecture-debate` → a deliberation structure showing the disagreement: positions,
  who holds them, what supports or objects to what, and the decision.
- `product-brainstorm` → a mindmap that reflects the late regrouping ("reduce the ask",
  "guide the ask", import, instrumentation).
- `incident-review` → a timeline or sequence diagram, plus causes.

Utterances carry real per-person identity; positions on the canvas should name the
people who hold them. Speculate and commit prompts may diverge — speculation should be
biased toward extending what exists, commit toward getting the form right.

**Part two — restructure.** Verify the pass fires on a long enough replay (concatenate
fixtures in the harness if needed — a harness option, not a new fixture). Verify it
improves rather than churns: ids for surviving ideas preserved, stale blocks deleted,
and it does not fire when the canvas has not meaningfully grown since the last pass
(add a cheap growth check in `src/room.ts`; a count of commits that changed the canvas
is enough). Tune `RESTRUCTURE_EVERY`.

Because the model is not deterministic, the bar is: **two out of two eval runs per
fixture** meet the criteria, with zero rejected ops in both.

Record what you tried, including what made things worse — that is more useful to the
next person than the final prompt alone.

Latitude: all prompt wording, cadence constants, the growth heuristic. Not open: diagram
types outside `MERMAID_HEADS` (`src/canvas.ts:27`); a third model tier; a separate
restructure pipeline; any change to the ops contract.

## Known failure to fix first (found at C2b, real browser)

`incident-review` produced a `timeline` block with quoted periods containing a colon
(`"14:02" : Gateway deploy ...`). Mermaid's timeline parser rejects it and the block never
renders. Teach the prompt (in `src/prompt.ts` only): timeline period labels must not contain
a colon or quotes (write `14h02` or `1402`), and the same for any diagram-type quirk you find
by running the fixtures. This is the kind of failure part one of this ticket exists to remove.
